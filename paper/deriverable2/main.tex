\section{Introduction}
The algorithm of sparse matrix-dense vector multiplication (SpMV) is an optimized version of the traditional matrix-vector multiplication
designed to handle cases where the matrix is organized in a low density of non-zero entries. 
This technique is particularly useful in scenarios that involves very large sparse matrices because it allows to reduce the used space for 
storing that large structures and, at the same time, optimizes memory access patterns during computational steps. 

Because the SpMV multiplication should handle matrices with millions or billions of not null elements, to obtain good results is necessary to use parallelization techniques 
on GPUs rather than sequential solution for CPUs. 

\section{Problem Statement}
In the SpVM multiplication we consider a matrix coded in a sparse format (in this case the CSR format) and an input vector that has the same size of its columns number. 
\\
Each elements of the resulting vector is computed by performing the dot products of each not null elements of the matrix with the input vector and accumulating them in the corresponding row position.
\\
The main objective of this report is to propose a common solution for the SpMV for CUDA devices and propose more advanced optimizations techniques to improve the overall performances.

\subsection{Storage Format}
The CSR for sparse matrices is a storage format that involves three different arrays to represent the information: 
\begin{itemize}
    \item The data array, that contains all not null terms of the original matrix.
    \item The column array, where for each element in the data vector specifies its column coordinate.
    \item The row array, which contains the start and the end pointers for each row to the data and column arrays. these two pair of pointers indicates which nut null terms in the data array are contained in that specific row. 
\end{itemize}
The size of the data and column arrays depends on the number of not null elements and the size of the row array depends on the number of the rows in the original matrix.

\subsection{Parallelization}
To improve the overall performance, the parallel implementations of the first algorithm are designed to be executed on Nvidia GPUs and programmed in CUDA.
The CUDA language model permits to run a kernel on different concurrent threads, which are scheduled and executed by computational elements called CUDA cores. 

To improve the performance and the organization of the parallel algorithms, CUDA architectures provides:
\begin{itemize}
    \item {\it{Warp organization}}, where groups of 32 threads are able synchronize and share data using predefined functions.
    \item {\it{Block organization}}, where more warps can syncronize themself using atomic operations, barriers and have access to a dedicated shared memory.
    \item {\it{Shared memory}}, which is a fast but limited memory divided in more blocks and used to improve data reusage, optimize the global memory transfers and other purposes. 
    \item {\it{Read only cache}}, which is a L1 read only cache that can be assigned by the programmer with the $\_\_ldg()$ function to improve data transfer for casual and repetitive accesses. 
\end{itemize}

\subsection{Warp reduction}
In CUDA architectures there are predefined mechanisms to allow threads in the same warp to exchange data. The function $\_\_shfl\_down\_sync()$ permit to perform a reduction of arrays with maximum length of 32.
For example, the function $reduceSum(acc)$ uses five shuffle functions to accumulate all contribution given by threads in the same warp on the thread 0. 

\begin{algorithm}[h]
\caption{Warp reduction system}
\begin{algorithmic}[1]
\Procedure{reduceSum}{acc}
\State $acc=\_\_shfl\_down\_sync(0xffffffff,acc,16)$
\State $acc=\_\_shfl\_down\_sync(0xffffffff,acc,8)$
\State $acc=\_\_shfl\_down\_sync(0xffffffff,acc,4)$
\State $acc=\_\_shfl\_down\_sync(0xffffffff,acc,2)$
\State $acc=\_\_shfl\_down\_sync(0xffffffff,acc,1)$
\EndProcedure
\end{algorithmic}
\label{alg:reduceSum}
\end{algorithm}
\subsection{Ceiling division}
The ceiling division is a system used to divide almost equally N elements across C equal size cells:
\begin{equation}
cellSize=\frac{N + C - 1}{C}
\label{eq:ceiling}
\end{equation}
From the obtained division, the {\it{start point}} and the {\it{end point}} for each cell are defined by:
\begin{equation}
start=cellSize*cId
\end{equation}
\begin{equation}
end=min(start+cellSize,N)
\end{equation}

\subsection{Binary Search}
The binary search is an algorithm that finds the position of a certain element in a sorted array with a logarithmic complexity $O(log(n))$. The proposed kernels use a modified version 
of the original algorithm to identify the position of the element nearest but lower or equal than the given value.  
\begin{algorithm}[h]
\caption{Adapted binary search}
\begin{algorithmic}[1]
\Procedure{binarySearch}{array,size,element}
\State $index=-1,\ left=0\ right=size$
\While{$left<=right$}
\State $mid=(left+right)/2$
\If {$array[mid]<=value$}
\State $index=mid$
\State $left=mid+1$
\Else 
\State $right=mid-1$
\EndIf
\EndWhile
\EndProcedure
\end{algorithmic}
\label{alg:binarySearch}
\end{algorithm}

\section{Methodology and Contributions}\label{sec:methodology}

\subsection{Dynamic algorithm (Parallel-2)}
In the first dynamic algorithm, the matrix and the vector are processed using a row based algorithm that assigns a thread for each row:
\begin{enumerate}
    \item The {\it{rowArray}} is splitted in equal subsection for different blocks using the ceiling division (\ref{eq:ceiling}). 
    \item For each block a variable in the shared memory $pendingRow$ is initialized to 0 and used to contain the next row number that is waiting to be processed. 
    \item Each thread uses the function $atomicAdd(pendingRow,1)$ to increment the value of $pendingRow$ and, at the same time, read its content.
    \item Using the value obtained, each thread computes the products and the accumulation of the entire row, saves the result in the output array and repeats step 3 and 4 until the block reach the end of its subsection. 
\end{enumerate}

\begin{algorithm}[h!]
\caption{Dynamic SpVM algorithm}
\algorithmicrequire~input, output and matrix structures.
\begin{algorithmic}[1]
\Procedure{vmcsrMul}{$output$, $matrix$, $input$}
\State $blockStart,blockEnd$ \Comment{Ceiling division}
\State $pendingRow\leftarrow0$ \Comment(only thread 0);
\State $row=atomicAdd(pendingRow,1)+blockStart$
\While {$row<blockEnd$}
\State $startRow,endRow$
\State $\ \ \uparrow rowArray[row],rowArray[row+1]$
\State $acc=0$
\While{${startRow<endRow}$}
\State $col=colArray[startRow]$
\State $acc+=$
\State $\ dataArray[startRow]*input[col]$
\State $startRow++$
\EndWhile
\State $output[row]=acc$
\State $row=atomicAdd(pendingRow,1)$
\State $\ \ +blockStart$
\EndWhile
\EndProcedure
\end{algorithmic}
\label{alg:dynamic1}
\end{algorithm}

\subsection{Optimized Dynamic algorithm (Parallel-5)}
The dynamic algorithm can be improved further using a better organization of workload between threads. More performance can then be obtained by:
\begin{itemize}
    \item {\it{Using the binary search}} in a preliminar kernel (\ref{alg:blockDivisionKernel}) to assign the rows to each block in base of the number of not-null elements of the matrix.
    \item Instead a single thread, {\it{Assigning a warp for each row}}. In this way, the threads in the warp process 32 partials from very long rows that can per reduced using the {\it{reduceSum}}(\ref{alg:reduceSum}).
    \item Assigning the read only cache on the input vector to improve the speed by leveraging on the data reusage.
\end{itemize}

\begin{algorithm}[h]
\caption{Optimized dynamic algorithm (Parallel-5)}
\algorithmicrequire~matrix structure, block division array, input vector and output vector structures.
\begin{algorithmic}[1]
\Procedure{vmcsrMul}{$output$, $matrix$, $input$, $blockDivision$}
\State $blockStart,blockEnd$ \Comment{binary search kernel}
\State $pendingRow\leftarrow0$ \Comment(only thread 0);
\State $row=\underline{Row Election}$ 
\While {$row<blockEnd$}
\State $startRow,endRow$
\State $\ \ \uparrow rowArray[row],rowArray[row+1]$
\State $acc=0$
\While{${startRow<endRow}$}
\State $idx=min(startRow+laneId,endRow)$
\State $col=colArray[idx]$
\State $acc+=fmaf($
\State $\ \ dataArray[startRow],\_\_ldg(input[col])$
\State $\ \ *(startRow+laneId<endRow))$
\State $startRow++$
\EndWhile
\State $acc=\underline{ReduceSum}$
\If {$laneId==0$}
\State $output.dataArray[row]=acc$
\EndIf
\State $row=\underline{Row Election}$ 
\EndWhile
\EndProcedure
\end{algorithmic}
\label{alg:dynamic2}
\end{algorithm}

\begin{algorithm}[h]
\caption{Row election System}
\begin{algorithmic}[1]
\Procedure{RowElection}{}
\If {$laneId==0$}
\State $row=atomicAdd(pendingRow,1)$
\State $\ +blockStart$
\EndIf
\State $\_\_shfl\_sync(0xffffffff,row,0)$
\EndProcedure
\end{algorithmic}
\label{alg:rowElection}
\end{algorithm}

\begin{algorithm}[h]
\caption{Preliminar kernel}
\algorithmicrequire~matrix structure, block division array initialized on global memory.
\begin{algorithmic}[1]
\Procedure{vmcsrDiv}{matrix,blockDivision} 
\State $blockStart,blockEnd$ \Comment{Ceiling on notNull array}
\If {$blockIdx.x==0$}
\State $blockDivision[0]=0$
\State $blockDivision[blockDim.x]=rowSize$
\Else 
\State $blockDivision[blockIdx.x]$
\State $\ \uparrow \underline{binarySearch(rowArray,rowSize,blockStart)}$
\EndIf
\EndProcedure
\end{algorithmic}
\Comment{Kernel launched for row division based on binary search. The kernel should be launched with same number of block of the main kernel with size equal to 1 thread}
\label{alg:blockDivisionKernel}
\end{algorithm}


\subsection{Shared cooperative algorithm (Parallel-6)}
The algorithm {\it{parallel-5}} shows poor performances when considering heavily unbalanced matrices. Another approach that tries mitigate those cases divides the shared memory as a buffer where the workload is divided by threads in the same block:
\begin{itemize}
    \item {\it{sharedBuffer}}, a space of size $B=blockSize.x*N$ used as buffer to contain the result of the multiplication between elements of the matrix and the input vector (each thread operates at max on $N$ elements).
    \item {\it{loadedRows}}, a space of {$R=blockSize.x$} cells used as cache for parts of the CSR row vector (each threads loads one pointer).
    \item {\it{rowsBuffer}}, a space of {$R-1$} cells used for accumulating partials for a small amount of rows (almost each thread maintaines one cell). 
\end{itemize}
Using these three different shared spaces, each block performs these steps:
\begin{enumerate}
    \item The entire block cooperates to {\it{prepare the shared memory}} for processing {$R-1$} rows by initializing with zeroes the {\it{rowsBuffer}} space and loading the necessary CSR pointers from the row array in the {\it{loadedRows}} space.
    \item The threads {\it{load a block of elements}} (maximum $B$ elements) from the matrix and the input vector in a fully coalesced way, perform the multiplications and store the result in {\it{sharedBuffer}}.
    \item The loaded elements {\it{are divided then in equal strides}} using the ceiling division (\ref{eq:ceiling}) where each thread performs a binary search on {\it{loadedRows}} space to identify the correspondent row index of the first elements of their strides. Then the strides are reduced in partials and accumulated in the {\it{rowsBuffer}} using $atomicAdd()$ in base of the correct row indexes.
    \item The step 2 and 3 are performed until all necessary elements for the considered rows in {\it{loadedRows}} are processed.
    \item {\it{Each threads stores one result}} from the {\it{rowsBuffer}} to the output vector in the global memory.
    \item All steps from 1 to 5 are repeated until all the rows of the matrix are processed. 
\end{enumerate}
The procedure \ref{alg:shared1} shows a heavily simplified representation of the shared cooperative algorithm.
\begin{algorithm}[h!]
\caption{Shared cooperative algorithm}
\algorithmicrequire~matrix structure, block division array, input vector and output vector structures.
\begin{algorithmic}[1]
\Procedure{vmcsrMul}{$output$, $matrix$, $input$, $blockDivision$}
\State $blockStart, blockEnd$ \Comment(From binary search kernel).
\State $sharedBuffer, rowsBuffer, loadedRows$
\For{$[0,(R-1)]\ \text{rows}\ \textbf{in} [blockStart,blockEnd]$}
\If{$threadIdx.x\ <\ R$}
\State $loadedRows[threadIdx.x]\leftarrow rowArray$
\State $rowsBuffer[threadIdx.x]=0$
\EndIf
\For {$[0,B]\ \textbf{in}[loadedRows[0],loadedRows[R]$]}
\For {$tId\ \textbf{in}\ [0,B], \textbf{coalesced}$}
\State $sharedBuffer[tId] \leftarrow dataArray[tId]$
\State $\ \ *\ \_\_ldg(input[colArray[tId]])$
\EndFor
\State $tStart,tEnd\leftarrow$ \underline{Ceiling on B}
\State $row\leftarrow \underline{binarySearch\ (loadedRows,B,tStart)}$
\For {$i\ \textbf{in} [tStart,tEnd]$}
\State $row\leftarrow\underline{row\ adjusting}$
\State $atomicAdd(rowsBuffer[row],i)$
\EndFor
\EndFor
\If{$threadIdx.x\ <\ (R-1)$}
\State $output\leftarrow\ rowsBuffer[threadIdx.x]$
\EndIf
\EndFor
\EndProcedure
\end{algorithmic}
\label{alg:shared1}
\end{algorithm}

\subsection{System Description}
The system used for the execution of the benchmarks uses CUDA 12.3.2 for compiling the source code, and is composed by a Intel(R) Xeon(R) Silver 4214 CPU and A Nvidia A30 GPU. The Nvidia A30 is based on Ampere architecture and has 56 Stream Multiprocessors with 96KB available shared memory per block.
The maximum memory bandwidth is $933GB/s$ and the $FP32$ performance is of $10.32TFlops$ 

\subsection{Experimental Set-up}
The performance is measured using the value of GFlops obtained by the execution time elapsed measured with $cudaEventRecord$ functions for CUDA algorithms and considering also the DRAM troughput, Compute utilization and Shared memory efficiency. 
\\
The results obtained by the three kernels are then compared with the library cuSPARSE\cite{cuSPARSE}, the official library supported by Nvidia.
\subsection{Block size estimation}
The parameters used for launching the kernels are calculated empirically in base of the amount of shared memory available per block, the number of cuda cores per SM and the size of the input matrix. In particular:
\begin{itemize}
    \item We choose the number of blocks equal to the number of not null elements of the input matrix divided by a constant obtained empirically of around 3328 ($notNull/NotNullPerBlock$).
    \item In the kernel \ref{alg:shared1}, the dimension of the shared memory is related on the number of elements that each thread should load and the block dimension ($shared=(elementsPerThread+2)*blockDim*sizeof(float)$).
    \item We can obtain the number of threads per block by considering $N$ block active at the same time in a Stream Multiprocessor, which is limited to the shared memory for the kernel {\it{parallel-6}}. In this case we consider the number of 
            threads equal to $sharedPerSM (Kb)\div[N*(elementsPerThread+2)*sizeof(float)]$. From various benchmarks, the best performances are obtained when considering $N=2$ and $elementsPerThread=14$. For the kernels {\it{parallel-2}} and {\it{parallel-5}} the number of threads can also be fixed at a value of 512 or 256 to obtain stable performances.
\end{itemize}
